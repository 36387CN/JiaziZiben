#概念

该系统通过将设备接收的GPS数据与Vuforia的AR基金会进行的底层AR追踪混合来工作。AR+GPS

无论是在AR Foundation还是Vuforia中，AR追踪都会移动摄像机（从世界坐标的起点开始）以匹配设备的真实运动。

系统做的是计算GPS定位物体相对于用户/相机的位置和方向，包括位置和方向。AR+GPS

为此，必须在场景中存在 at object 作为 AR Tracker 使用的 的兄弟单位。因此，在AR基金会中，它将是的子节点，而在Vuforia的情况下，它将被置于场景的根源。ARLocationRootAR CameraAR Session Origin

该对象必须包含a和a两个分量。这些组件将确保游戏对象与地理方向对齐，从而正确定位。ARLocationRootARLocationManagerARLocationOrientationARLocationRoot

它负责设备接收的所有GPS数据。它可以放置在场景的任何位置。这些数据通过所使用的配置进行过滤。ARLocationProviderARLocationProvider

这些组成部分是系统的基础。所有实际将物体放入场景的组件都会监听它们发出的事件以执行所有更新。AR+GPS

#海拔

由于移动设备提供的高度数据通常不可靠，插件中有几种不同的高度指示方式。根据所选模式，所有位置的属性都会有不同的解释。Unity AR+GPS LocationAltitude

  • Absolute使用设备的高度数据，并将其视为相对于海平面的绝对值。Altitude
  • DeviceRelative认为 是相对于设备。Altitude
  • GroundRelative认为 相对于最近探测到的地面平面。Altitude
  • Ignore计算时可以忽略高度。

#稳定性与精度

稳定性和精准度之间存在一定的权衡;更多的测量通常意味着更高的精度，但物体也会随着每次位置更新而移动，破坏稳定性和体验的持久性。

有两种情况下，物体会因系统而移动：当位置更新时，以及当方向更新时。AR+GPS

因此，为了让对象看起来更稳定，可以在各个组件中使用较低的值，或者在 和 中使用较低的值（但不要为零，因为零意味着无限次更新）。Max Number Of Location UpdatesARLocationProviderARLocationOrientation

#ARLocationManager

组件管理插件与底层AR会话之间的接口。该组件是系统运行所必需的。ARLocationManagerAR+GPSAR+GPS

它应该放在物体中，这个对象要么是（AR Foundation）的子节点，要么是场景的根节点（Vuforia）。ARLocationRootAR Session Origin

房产：

  • Camera用于渲染AR内容的AR摄像机。如果未设置，将使用标记为“MainCamera”的相机。
  • Wait For AR Traking To Start如果属实，请等AR追踪开始，更新位置和方向以及物体位置。推荐。
  • Restart When AR Tracking Is Restored如果属实，每次AR追踪丢失和恢复时，AR+GPS系统都会重启，重新定位所有物体。
  • Set Target Frame Rate To 60Mhz如果为真，管理器会将“Application.targetFrameRate”设置为60。
  • Debug Mode启用调试模式后，该组件会向控制台打印相关消息。在日志输出中通过“ARLocationManager”进行筛选即可查看消息。

活动

  • On Tracking Started当AR追踪首次开始时发出。
  • On Tracking Lost每当AR追踪丢失时都会发出。
  • On Tracking Restored每当AR追踪丢失后恢复时都会发出。

#ARLocationProvider（工作分配者）

该组件管理来自GPS和磁传感器的所有数据。数据会根据所用设置进行过滤，但你也可以访问原始数据。该组件是系统运行所必需的。AR+GPS

房产：

  • Time Between Updates连续位置更新之间的最短时间。
  • Min Distance Between Updates触发位置更新的最小距离。
  • Accuracy Radius目标精度半径。例如，将此设置为25时，会阻挡误差半径大于25米的数据。
  • Max Number Of Updates全球最大位置更新次数。设置到较低的数字有助于阻止物体的移动或重新定位。也可以为每个组件单独设置。
  • Mock Location Data编辑器中使用的模拟位置。
  • Max Wait Time启动时等待位置启用的最长时间。
  • Start Up Delay它为定位提供商设置一个延迟，以便开始请求更新。在使用Unity Remote时非常有用。
  • Debug Mode启用调试模式后，该组件会向控制台打印相关消息。在日志输出中通过“ARLocationProvider”筛选即可查看消息。

活动：

  • On Enabled当首次位置读数被接收时发出。
  • On Location Updated每当接收到新的（过滤过）位置数据时都会发出。
  • On Raw Location Updated每当接收到新的（原始）位置数据时都会发出。
  • On Compass Updated每当接收到新的罗盘/航向数据时都会发射。

#ARLocationOrientation

该组件通过利用设备的磁传感器数据，管理游戏对象的朝向，使其与地理方向同步。它应该放在游戏对象上，并且是系统运行所必需的。ARLocationRootARLocationRootAR+GPS

房产：

  • Max Number Of Updates最多的迎新更新。更新将在此数值后暂停。零表示没有限制，更新不会自动暂停。
  • Average Count只有在测量航向N次并取平均值后才更新。
  • Low Pass Filter Factor这是加在航向值上的低通滤波因子，用于减少抖动。值为零时禁用低通滤波器，而值为1时，滤波器会阻挡所有值变更。
  • Use Raw Until First Average如果设置为 true，使用原始航向值直到测量第一个平均值。
  • Movement Smoothing Factor方向旋转在变化时的平滑因子。零表示被禁止。
  • True North Offset对设备计算的真北方向进行自定义偏移。当设置为非零值时，设备的真北将被忽略，并被加到该偏移量上的磁头取代。
  • Apply Compass Tilt Compensation On Android如果属实，可以在安卓设备上应用倾斜补偿算法。

活动：

  • On Orientation Updated在迎新更新后发出。
  • On Before Orientation Updated在方向更新前发出，新的欧拉角作为论证。y

#地点地点

该组件会将其绑定的游戏对象放置在给定的地理位置。这是放置GPS定位AR内容最简单的方式。

房产：

  • Location Input Type所使用的位置坐标输入类型。要么用“Location”直接输入位置坐标，要么用“LocationData”来使用ScriptableObject。
  • Location在这里输入所需的GPS坐标。
  • Location Data一个LocationData可脚本对象，存储用于放置目标的GPS坐标。
  • Override Altitude Data如果为真，覆盖LocationData的高度。
  • Movement Smoothing由于GPS位置调整，移动的平滑因子;如果设置为零，则该系统被禁用。
  • Max Number Of Location Updates该物体受GPS位置更新影响的最大次数。零意味着没有限制。
  • Use Moving Average如果属实，使用移动平均滤波器。
  • Hide Object Until It Is Placed如果为真，该对象将被隐藏，直到放置在地理位置。如果有，会启用/禁用MeshRenderer或SkinnedMeshRenderer，并启用/禁用所有子游戏对象。

活动：

  • Object Location Updated当对象位置更新时，事件被调用。参数包括当前的GameObject、位置以及该对象迄今收到的位置更新次数。
  • Object Position Updated当对象位置在位置更新后被更新时调用事件。如果移动平滑大于0，则该事件将在位置更新事件之后触发。参数包括当前的GameObject、位置以及该对象迄今收到的位置更新次数。

#故障排除

避免常见错误的一些建议：

  • 确保你的设备有可用的GPS和磁性传感器。
  • 使用AR Foundation时，务必确认是否安装了ARKit和/或ARCore。
  • 使用Vuforia时，确保软件包已安装，但ARKit和ARCore未安装。AR Foundation
  • 不要在安卓上使用横屏模式，因为倾斜补偿算法目前不支持横屏。
  • 一定要确保 被标记为 ，或者它被设置为 属性。AR CameraMainCameraARLocationManagerCamera
  • 使用Vuforia时，确保位置追踪已激活。
